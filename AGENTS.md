# Partition Writing

For writing or editing on the user's behalf, inspect `.partition/private/writing/library.json`
when it exists. Choose the category matching the CURRENT task and audience. Read
that category's GUIDE.md and NEW.md or EDIT.md, then relevant original samples.
Read private instructions, preferences and relevant reviewed context. Do not load
unrelated samples, raw memory imports, historical backups or other writing tones.
Current user instructions override stylistic observations. Never infer biographical
facts from fiction, academic arguments or quoted sources. Preserve meaning in edits,
ask for missing facts in new writing, and never fabricate citations or plagiarize samples.
If these local files are unavailable, ask for an exported style prompt; do not claim
to have read inaccessible files. This is context-based style adaptation, not training.

For application maintenance, read README.md, SETUP_FOR_AGENTS.md and docs/library.md.
Preserve the compatibility private storage path and IDs during migration. Originals
must remain intact. Keep generated source evidence category-specific and validate
model output before filesystem writes. Run the full unittest suite and JavaScript
syntax check. Never commit private libraries, credentials, screenshots of user data
or conversation history. Public source may only use synthetic test fixtures.
